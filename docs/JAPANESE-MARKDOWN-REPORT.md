# 日本語診断レポート

［診断所見］または［診断ツールへの引き渡し］の ZAP 欄で［診断レポートを出力］を押します。出力後、プロジェクトの `reports/<出力日時>/` を開きます。

- `engagement-report.ja.v2.docx`: 顧客提出用のWordレポート。
- `report-document-v2.json`: Word、Markdownなどの共通元となる構造化レポート。
- `engagement-report.ja.md`: 日本語の Markdown レポート。
- 従来の JSON、HTML、警告要約、候補作業表も同じフォルダーに出力します。

## ScopePilot独自の報告構造

顧客向けWordレポートは、意思決定情報、診断保証情報、技術証跡の三層で構成します。第三者報告書の文章、表組み、章順、配色、商標、著作権表記は使用しません。

| 報告要素 | ScopePilot の出力・入力元 |
| --- | --- |
| 表紙・案件情報 | 案件名、開始 URL、生成日時、レポート形式と日本語辞書の版 |
| 診断実施の情報 | 許可 Origin、ロール、操作制約、記録上の観測期間、通信数・候補数 |
| 全体の結果 | 探索所見数、警告種類・ロール別件数、発生記録数、ZAP の危険度別内訳 |
| 評価の根拠 | ZAP の危険度・確度と所見の記録値。総合評価と攻撃難易度は未判定・未評価 |
| 対象ページ | 観測通信・採用候補・警告発生箇所の URL と記録済みページ名 |
| 指摘の索引 | W 番号のツール警告、F 番号の探索所見、危険度、状態、発生記録数 |
| 個別の結果 | 一般的な日本語解説、対応案、対象メソッド・URL・パラメータ、検証済み原文、CWE/WASC |
| 根拠・再現情報 | 原本の相対パス・JSON Pointer・SHA-256・検証状態。再現手順や実影響は未記録 |
| Brunoでの手動確認 | B番号、担当者が記録した確認結果、SHA-256で照合したHTTPリクエストとHTTPレスポンス |
| 対応管理 | 指摘番号ごとの対応方針・担当者・期限・再確認結果の記入欄 |
| 補足・出典 | 日本語解説の ZAP 公式ルール資料、関連ファイル |

依頼者、担当者、診断実施期間、診断元 IP、連絡先など記録していない情報は、提出前の記入項目として出力します。観測日時や取込日時で補って事実として扱いません。Markdown を編集して補足できます。

## 日本語解説と原文

初版の辞書は ZAP のルール ID 10010、10011、10015、10017、10020、10021、10023、10035、10036、10037、10038、10054、10055 の13種類に対応します。Cookie、応答ヘッダー、キャッシュ、外部スクリプト、デバッグ情報などの一般的な解説・対応案を用意しています。

解説はルール群の要約です。欠落、重複、構文不備などの個別の種類は原警告名と原文を参照します。検証済み原文の説明、対策、参考情報を併記し、未登録ルールは「日本語解説未登録」と表示します。汎用的な自動翻訳ではなく、外部翻訳サービスへ案件情報を送信しません。既存の探索所見は記録された言語で掲載します。

## 原本と集計の扱い

ZAP 原本はプロジェクト内の相対パスを解決し、64 MB の上限、SHA-256、JSON Pointer、ルール ID を検証します。同じ原本は一度だけ読み込みます。欠落や改変がある場合は警告の基本情報を残し、詳細を載せられない理由を表示します。誤った原本から説明を補いません。

警告はツール・ルール ID・原警告名・危険度・確度・ロールごとに集約し、個別の通信と出典を残します。発生記録数と集約後の件数は分けて表示します。件数だけから脆弱性の確定や総合評価を決めません。警告がない場合も、未実施の診断を完了扱いにしません。

Markdown は UTF-8 で保存します。外部由来の文字列の HTML・Markdown 記号をエスケープします。通常の観測 URL の認証情報、クエリ、フラグメントと、ZAP の attack/evidence/otherinfo、通常のHAR本文は新しい Markdown へ転記しません。Brunoで手動確認した通信は例外として要求・応答を一組で掲載します。Cookie・Authorization・一般的な機密フィールドは伏せ字にします。共有前に内容を確認してください。ローカルの原本や従来の JSON/HTML はそれぞれの既存仕様で保持します。
