### ZAP 実測で発見した製品課題と対応

1. **ZAP daemon が起動しない** (環境): 10/2 由来の stale `.homelock` と、失敗 instance が残した HSQLDB session lock (心跳時刻が未来側で不正判定) で全起動が失敗。stale lock ファイル除去で解決。製品側は利用不可能エンジンを正しく拒否した (feature must stay unpublished)。
2. **proxy 経由 HTTPS で証明書エラー**: ZAP の再署名証明書を fresh context が信頼しない。proxy 明示時のみ `ignoreHTTPSErrors` を有効化 (自前 proxy 限定)。
3. **1 件の navigation 失敗で探索全体が異常終了**: scope 内 URL からの redirect が scope 外 HTTPS へ飛び証明書エラー → 探索が throw。`net::ERR_*` 等の navigation 失敗は status 0 (`application/x-navigation-failure`) の観測として記録し続行するように修正。実装バグは従来どおり throw。

## 第 8 次 (深夜): 次段階バックログの一括解消

### 実装 (一般化)

1. **書き込み API 発見 (スクリプト解析)**: `extractScriptApiCalls` (adapter) — 読込済み
   bundle から HTTP 呼び出し定義を抽出。直接呼び出し (`.post(this.hostServer+\`/path\`)`) と
   サービス基底ペアリング (基底パス代入 + 次の基底までの動詞) の 2 形式。契約に
   `PageObservation.scriptApiCalls` を追加 (OpenAPI 更新)。core で api-endpoint 候補化
   (観測済みリクエストと重複排除)。OPTIONS/Allow 方式は CORS middleware が全 OPTIONS を
   横取りし虚偽のメソッド広告を返す対象があるため不採用 (実測で確認)。
2. **トランスポート経路の候補化除外** (候補ランキング): socket.io 等の well-known リアルタイム
   通信チャネルを api 候補化から除外 (エフェメラルなポーリング URL が候補枠を圧迫する問題)。
3. **候補の横断重複排除**: 同一スクリプトが複数ページで読み込まれると候補が毎ページ複製される
   (実測 24,963 件) 問題を、観測横断でカテゴリ×method×URL×入力点のキーで一意化 (266 件に)。
4. **具体化 ID の優先付け**: 複数ページで観測された識別子 (中心的エンティティ) を優先して
   ルート具体化に使う (同頻度は観測順)。
5. **payload 実行検証**: `verifyPayloadExecution` (explorer port・adapter: dialog/pageerror 監視・
   自動 dismiss・scope 強制) と `verifyFindingExecution` (service: role session・証跡保存) を実装。
   所有 fixture の DOM XSS ページで実 chromium の alert 発火検出を結合試験で確認。
6. **client-side 13 件の製品要件化**: `docs/design/30-client-side-capabilities.md` を作成
   (実行検証・依存静的解析・コンポーネント DB 照合・暗号素材・機密漏洩の 5 領域と段階)。

### 実装

- core (`runActiveScan`): 所見取込直後に反射系 XSS 所見 (title が XSS 系・URL に payload 印字あり)
  を最大 5 件選び、browser (payload 実行検証) で実行確認する。検証結果は
  `ActiveScanRunResult.payloadVerifications` (findingId・executed・signals・証跡参照・error) に載る。
  検証失敗は診断全体を失敗させず結果に記録する。browser 検証非対応の explorer 構成では実行しない。
  進捗 event も発火する (engine scopepilot・「payload 実行を browser で検証」)。
- `verifyFindingExecution`: 証跡 label に findingId を使う入力を追加 (連続実行時の label 衝突回避)。
- OpenAPI: `ActiveScanRunResult.payloadVerifications` を追加。
- UI (wizard): 診断結果サマリに「ペイロード実行検証完了 (N件中M件で実行確認)」を追記
  (resources.ja/en 追加、`ScanRunResultView` に型追加)。api-server は結果を丸ごと透過するため
  サーバ側の変更は不要。
- 試験基盤: `createTestService`/`bootstrapFlow` に `scanEngine` 差替え option を追加。

### 検証 (第 9 次)

- 単体試験 (`payload-execution-wiring.test.ts` 3 案例): XSS 所見の自動検証と結果載せ・
  dialog 不発火の陰性判定・対象外所見 (payload なし URL・非 XSS) の非検証。
- 通常診断フローの回帰実測 (未認証・15 対象): 探索 15 ページ → 候補 114 → ZAP 診断 15 秒 →

  (ZAP の SQLi 所見のみのため payloadVerifications 無し・診断完了)。
- 全ワークスペース試験 fail 0・型検査成功。
