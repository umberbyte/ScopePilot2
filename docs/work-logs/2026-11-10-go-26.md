# GO-26: 実行状態機械の統一

正本は `spec-gap-resolution` ワークツリーの `docs/design/41-spec-gap-resolution.md` §6を参照した。

- 通常遷移とcrash recoveryを分離。Interruptedへの通常遷移を拒否し、全終端からの再開を拒否する。
- 非同期scan APIは共通のRunStateMachineを使い、state/runStateにcanonical値を返す。dispatchStateは別管理し、queue中はConfirmedとする。停止通知だけでStoppedにせず、処理と保存の完了を待つ。
- GO-25 (`2b2d053`) のscan経路・schemaを土台として取り込み、状態投影とreason制約だけを更新した。startの202/executionIdなど既存応答構造は維持する。
- engine起動・停止・最終保存障害をFailedに記録する。Nuclei/workflow step失敗時もrun全体をFailedとし、完了済みstepの結果を保持する。abortフラグだけで実障害を協調停止に置き換えない。
- 保存時にstop reason、遷移、run識別子、attemptの整合性を検証する。再開には別runと増加したattemptが必要。
- migration version 5は旧Succeeded/Cancelled行だけをCompleted/Stoppedへ更新する。Succeededのreasonはcompleted、Cancelledは既存の協調停止reasonを保持し、不明なreasonはuser-requestへ補完する。canonical行・識別子・attempt・時刻は変更しない。
- design/22、detailed-design/01、UIの状態表示・翻訳資源を整合した。
