# GO-29: fixture fallback の廃止

設計正本: `spec-gap-resolution/docs/design/41-spec-gap-resolution.md` §9（別 worktree、読取専用）。GO-26/GO-25/GO-22 の変更には依存しない。

- `RuntimeProfile` は production / simulation / test。既定は production。Repeater / Fuzz / Sequencer / OAST / WebSocket / HTTP/2 は production で `adapterKind: real` を要求し、欠落・fixture・種別未宣言は送信前に `CapabilityUnavailable`（API 503）で拒否する。
- Core 内の合成応答・token 発行・送信台帳の代用を廃止。fixture は `tools/simulation/src/adapters/fixture-tools.ts` へ移し、simulation composition と test factory が明示注入する。実 engine を渡す harness は production とし、欠けた tool を補完しない。
- OAST 未設定は共通 `UnavailableCapability`。正式 adapter は種別・版を宣言する。
- `/api/capabilities` と Settings に runtime profile / adapter kind / 利用可否・制約を開示。API は構成時刻・版・fixture hash と runtime manifest hash も返す。探索・診断 run の開始前に manifest を証跡保存する。既存 runtime bundle hash を置換せず、manifest hash を追加する。
- UI の各 tool 送信ボタンは capability 取得まで、または利用不能時に無効化し、理由を表示する。fixture 構成では試験データであることを表示する。
- tool 結果に adapter kind を付与し、Fuzz / Sequencer / OAST の一覧にも保持する。production の fixture engine 計画は検証・確認・実行で拒否する。
