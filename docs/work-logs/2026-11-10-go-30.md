## 変更

`baseline-flow.ts` を5,566行から1,019行へ縮小した。`BaselineFlowService` の既存 public method と型の import 元を facade として維持した。API handler、OpenAPI、UI の呼出契約は変更していない。

1. public method の存在、案件・認可・hint・計画・確認・scope 縮小時の確認無効化を characterization test で固定。
2. 既存 domain `RunStateMachine` はそのまま使い、application 側の machine 生成と `RunSinkPort` への保存を `RunLifecycleService` に集約。証跡保存を `EvidenceService`、監査一覧を `EventPublisher`、runtime profile と adapter 判定を独立境界へ移動。
3. `CaseService`、`AuthorizationService`、`PlanService` を抽出。案件 aggregate、認可、文書 hint、hint seed の所有先を明示的な `CaseSessionContext` にした。確認の登録・失効参照には command/query port を使う。
4. Repeater/Fuzzer/Sequencer/OAST/WebSocket を機能別 service に抽出。各サービスは transport、案件 query、memory session query、通信記録・event port を受け取る。抽出した送信経路の暗黙 fixture 応答を除去。未構成・unavailable adapter と production の fixture adapter は、送信・結果台帳・所見・event の生成前に `CapabilityUnavailable` にする。既定 profile は production。
5. Session/Exploration/GuidelineExecution/DiagnosticRouter/JobOrchestrator を抽出。ブラウザ cookie/storage/header を含む状態は memory-only の `SessionVault`、実行結果・報告用 projection は workspace ごとの `ExecutionContext` が所有する。Finding/Report/Traffic/API import も専用 service に移した。相互呼出は内部 command/query port で接続し、facade が構成する。

fixture は `tools/simulation/src/fixture-tools.ts` から test/simulation の構成層で明示注入する。simulation harness の CLI fuzz 経路もこの注入を使用する。production adapter の実装・他 entry point の GO-29 全体移行を持ち込んでいない。既存の advanced transport/DOM/Proxy/CA/extension の入口は facade に残る。

## 維持した境界と後続移行

- 外部 API の handler から command/query handler への切替と facade 削除は §10.3 の後続段階。今回 facade を削除しない。
- 永続化は既存 `EvidenceStorePort` と各 sink/repository を引き続き使用。新しい cross-repository transaction、DAG scheduler、lease、共有 budget 制御の意味変更は行わない。保存と event の既存順序、復旧時の自動再開禁止、domain の canonical state machine を保持。
- case ごとに facade/context/vault を構成する。同一 facade に別案件を重ねて開く運用や、同一案件で複数 scan が同じ projection を同時に書く制御の新設は含まない。
- `SessionCoordinator` の既存 refresh/lockout bookkeeping を保持しており、実再認証 transport を新規実装したわけではない。
- EvidenceService へ渡す redacted projection と provenance は既存 caller のものを保持。新しい global redaction policy や secret の永続化は導入していない。
- push は行わない。ローカルで review 可能な変更として保全する。
