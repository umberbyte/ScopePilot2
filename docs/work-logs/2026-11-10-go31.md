# GO-31: 探索・静的素材・client 観測・候補順位

## 実装範囲

- 従来の `buildExplorationPlan(operator, seeds, limits)` はそのまま利用可能。第4引数または `POST /api/plan/explore` の `discoverySources` に `robots` / `sitemap` / `manifest` / `wordlist` を明示したときだけ隠れた経路の探索を追加する。ActiveCrawl 認可を必須とし、source を計画 hash に含める。wordlist は `discovery-1` の一般的な4経路で、対象固有語は含まない。
- robots の Allow/Disallow/Sitemap、sitemap の loc、manifest の start_url、JS module/source map の参照を同一 Origin 内で辿る。Disallow は認可ではなく発見資料として扱う。既知の欠落経路を負対照とし、本文 fingerprint が一致する推測経路を候補化しない。パスを反映する wildcard 応答も正規化する。本文が大きく変化する soft-404 を完全に識別するものではない。
- 明示された未認証静的資産は streaming 取得し、展開後1 MiB、redirect 5 hop、15秒、scope、通信予算を適用する。JS / map / JSON / manifest / text / XML / PEM / certificate を扱い、画像・動画・font・実行形式を除外する。認証・proxy 経路では既存の browser 観測を使う。browser での収集は補助的であり、取得できなかった素材を「検査済み」とはしない。
- 静的資産は URL / 発見元 / MIME / byte 数 / SHA-256 / analyzer version / 検査信号で表現する。本文・token・鍵値を API に返さない。`GET /api/observations/assets` は URL ごとに重複を除いた metadata を返す。生本文保存・本文 lazy-load API は今回追加しない。
- History / hash 遷移、browser request、Service Worker 登録**試行**を観測する。Service Worker の実行は引き続き禁止する。確認済み interactive diagnostic workflow の通信・経路を探索候補へ合成する。実際の POST 等と、script に定義されただけの API は区別する。hash 経路は URL の重複排除で消さない。
- 通信予算は browser の subrequest / redirect / WebSocket handshake にも適用する。ページ訪問数・時間・frontier 数を制限する。AbortSignal と HTTP client 切断で停止し、確認済み workflow にも通信数・時間制限を渡す。既存 facade と同期 API は維持する。
- 30.2: banner、package metadata、source map から依存名・申告版を抽出する。版不明や範囲指定を固定版へ推測しない。編集距離1の名称類似と限定した危険 API signature を、低 confidence の要確認信号として分離する。
- 30.3: 固定したローカル DB の名前・alias・stable semver の `[introduced, fixed)` を照合する。外部照会はしない。DB の source/version/hash を asset metadata と所見証跡へ保持する。
- 30.4: login の cookie/storage/header から JWT をメモリ内で受動検査する。none、exp 欠落、key reference、既知の弱い HMAC 鍵、配布公開鍵との署名照合、公開鍵との HMAC 混乱、公開鍵/証明書の algorithm・RSA bit 数を扱う。結果は fingerprint と検査内容のみ。token の受理確認は既存テーマ9の正規対照付き ActiveScan と区別し、受動観測だけで受理済みとは表示しない。
- 30.5: `client-review-1` の AWS access key / GitHub token / private key 形式と entropy を組み合わせる。値や周辺本文を出さず hash と REDACTED 表示だけを保存する。無効化確認・外部検証は行わない。static review の信号は証跡付きの未確認所見として取り込む。
- score / scoreSignals / provenance を追加し、観測通信、定義、仕様、入力点、source の中心性、複数ロール観測、静的素材、transport、状態変更 risk から安定順位を返す。実通信の候補を script 定義より優先して重複代表にする。順位は実行許可を変えない。wizard に順位と理由の tooltip を表示する。

## ローカル DB の設定

`SCOPEPILOT_COMPONENT_DB_PATH`、`SCOPEPILOT_COMPONENT_DB_VERSION`、`SCOPEPILOT_COMPONENT_DB_SHA256` を揃えて指定する。ファイルは4 MiB以下の JSON。

```json
{
  "source": "reviewed-snapshot-source",
  "version": "approved-version",
  "sha256": "SHA-256 of canonicalJson(entries)",
  "entries": [
    { "id": "ADVISORY-ID", "name": "package-name", "aliases": [], "introduced": "1.0.0", "fixed": "2.0.0" }
  ]
}
```

hash は `assetHash(canonicalJson(entries))`。固定版または hash の不一致は rollback を含め拒否する。起動時の snapshot を adapter が複製して保持する。正規の snapshot は別途審査・配備が必要で、所有 fixture の架空 advisory を製品 DB として同梱しない。現時点で prerelease、複雑な semver expression、OSV の全 ecosystem/range を扱うものではない。

## 検証

- `npm run typecheck`
- `npm test`（全 workspace）
- `npm run test:integration --workspace @scopepilot2/core`
- `SCOPEPILOT_PLAYWRIGHT_IT=1 node --test packages/adapters/test/playwright-explorer.integration.test.ts`
- `git diff --check`

最終結果: typecheck 成功、全 workspace は559件中558 pass / 1 skip / 0 fail、コア API 結合は40 pass、実 Chromium 結合は10 pass。既定 workspace 実行で skip される外部 runtime の gate と、今回明示的に実行した Chromium 結合は分けて集計した。

所有 HTTP fixture で decompression 上限、scope 外 redirect、応答途中の中止、binary 除外を確認。所有 Chromium fixture で認証 storage、History/hash、workflow request、登録試行、subrequest budget、外向き通信拒否を確認した。一般化した unit fixture で provenance、DB 改変/rollback、stable version 境界、未知版、低 entropy の負対照、秘密値の非露出、JWT/公開鍵、候補の安定順位を確認した。

追加の API 結合検証で既存 fixture の古い前提も修正した。document hint は禁止済み installer URL から一般の entry へ変更し、business logic には明示的な browser/login fake とログイン済み session を注入し、所見確定には現行 API が要求する再現・review・CVSS 欄を渡す。製品側の認可やレビュー要件は緩和していない。
