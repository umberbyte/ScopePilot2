## AGENTS.md更新の反映

追加された「全作業で利用者選択AIを利用できる」「UIをSimple / Advancedの2モードにする」方針と、
`docs/WebAppPentestGuidelines_診断項目_ScopePilot_作業用.xlsx`を診断templateの基準資料にする方針を設計へ反映した。

- `UiMode`と`OperatorPermission`、対象サイトの`TargetRole`を分離した。mode切替では権限が増えない。
- Simpleはガイドライン選択、自動クローリング後の対象選定、plan最終確認に操作を限定した。
- Advancedは権限内で探索・対象・template・request・判定・上限を編集できるが、安全制御は共通とした。
- desktop実行に`PlanConfirmation`、非対話CLI/CIに期限付き`AutomationGrant`を追加した。
- AI支援を文書hint/探索から全作業へ広げ、provider/model、入力hash、redaction、提案、採否を記録する。
  AI出力は提案に限定し、通常commandの権限・認可・scope・上限・最終確認を迂回させない。
- Excelは14sheetを読み取り、ガイドライン6sheet・769行、ZAP診断rule 102行、ZAP非対応代替94行を
  catalog入力候補とした。シミュレーション等5sheetはfixture/referenceに分離し、runtimeでExcelを直接実行しない。
  source hashは`33d32b195f84a36a77dd0eadeecfb490d0034a6dc6b2b41803af5ac8c99b882c`。
- workbookは読取専用で検査し、14sheetすべてでformula/error cellが0件であることを確認した。内容は変更していない。

## A0着手: モノレポ骨格とシミュレーションハーネス

`AGENTS.md`「シミュレーションハーネスを先に用意し、探索→能動診断→所見の自動完走を回帰テストの
基準にしてから本体を書く」に従い、実装を開始した。

### リポジトリ骨格

- npm workspaces (`apps/*`, `packages/*`, `tools/*`) とルート `tsconfig.json` を追加した。
  `detailed-design/01-system-components.md` 2章の配置どおりで、未実装パッケージはplaceholder。
- TypeScript は strict + `erasableSyntaxOnly` + `verbatimModuleSyntax` とし、Node 24 の型除去実行で
  `node:test` を直接 `.ts` に対して使う。実行依存は追加せず、dev依存は `typescript` と `@types/node` のみ。
- テスト段階分離のため、`npm test` は unit のみ、`npm run test:fixture` は simulation fixture を実行する。

### 契約とコアの seed

- `packages/contracts`: 基準シナリオに必要な型 (CommandEnvelope, DomainError, RunState, CaseScope,
  ExecutionPlan, EngineCapabilitySnapshot, PageObservation, EngineAlert, Finding, ReportModel,
  BaselineFlowEvent) と、正規化 JSON による `hashStable` (計画hashの規約) を定義した。
- `packages/core`: `ScopePolicy` (deny優先・canonical origin)、`PlanService` 相当 (計画の正規化・hash・検証)、
  `FindingImporter` (重複除外)、report builder、探索・診断の port、および基準シナリオを駆動する
  `BaselineFlowService` を置いた。command処理は権限判定→認可→確認→domain処理→証跡→eventの順とする。

### シミュレーションハーネス (`tools/simulation`)

- 固定fixture: 合成対象サイト (5ページ・scope外リンク込み)、ZAP alert API 出力 (poll別批次・重複込み)、
  Nuclei JSONL (供給のみ・取込はF18実装時)、engine 能力表 (fixture である旨を明記)。
- fixture adapter: 探索 (呼出し記録を残す)、ZAP相当 (入力・停止・`URL Does not Exist` 失敗を再現、停止は冪等)。
- 基準シナリオ runner: 案件作成→認可→探索→候補採用→能動診断→取込→所見→報告を UI なしで実行する。

### テスト

- UT: F01-UT-001, F01-UT-002 (scope-policy), F01-UT-003, F01-UT-004 (authorization-policy)、
  F08-UT-002 (exploration-planner budget), F11-UT-004 (scan-start-policy), F11-UT-006
  (scan-result-importer) を実装した。手書き fake と `BaselineFlowService` への注入で検証する。
- FT: F21-FT-001〜007 (`tools/simulation/test/fixture/baseline-flow.test.ts`) を実装した。
  自動完走と監査event順、計画hash・報告model hashの安定、scope外の送信前拒否 (Enforced) と
  adapter非呼出、alert重複除外と実影響未確認表示、版・能力表・fixture hash・overshoot予約の記録、
  `URL Does not Exist` 失敗の再現を検証する。
- `npm run typecheck`、`npm test` (unit 10件)、`npm run test:fixture` (FT 7件) がすべて合格。
