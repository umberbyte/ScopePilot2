## 増分#4: CaseAggregate と revision guard

`packages/core/src/domain/case-aggregate.ts` を新設し、`BaselineFlowService` を案件 aggregate 経由に改めた。

- `updateScope` は expectedRevision を比較し、不一致なら state を変えず `Conflict` (F01-UT-007, SYS-UT-002)。
- 縮小判定 (`isScopeNarrower`): 許可 origin 減・deny 追加・上限減。縮小時は登録済み confirmation を

- 権限 gate の検証も追加: 権限不足の command は案件 state も監査 event も変更しない (SYS-UT-001)。

## 一括実装 (利用者指示「区切らず一気に」): 増分#5〜#7 と横断UT

### 増分#5: run 状態機械・ScanMonitor (SYS-UT-004, F11-UT-005)

- `RunStateMachine`: Draft→Validated→Authorized→Confirmed→Running→Stopping→terminal の遷移表で検証し、
  不正な遷移は `ValidationFailed`、terminal state の再開は `Conflict` で拒否する。停止要求は Running から
  Stopping へ冪等。crash 検出 `detectInterrupted` は Running/Stopping を Interrupted へ変換し、自動再開しない。
- `ScanMonitor`: progress・alert cursor の poll と停止要求を担当。`requestStop` は冪等で adapter の
  stop を呼ぶのは初回だけ (F11-UT-005)。poll 反復上限に達したら失敗として扱う。
- `BaselineFlowService` の探索・能動診断は run 状態をこの状態機械で遷移させるように改めた。
  上限停止は Stopped、engine 失敗は Failed、完了は Completed に区別する (design/22 §2)。証拠保存失敗は
  取込 event を出さず EngineFailure (retryable) で失敗させる。

### 横断UT追加: F01-UT-005/008, SYS-UT-003/005/006

- `OperatorPolicy`: operator 名と対象 role 名の一致は権限付与の根拠にしない (F01-UT-005)。
- 認可証跡 metadata の白リスト化: 許可 field 以外 (秘密値らしき key 含む) を保存しない (F01-UT-008)。
  `EvidenceStorePort.saveText` が metadata を保持するよう拡張。
- `apiErrorOf`: domain error を安定した API code へ一意写像。DomainError 以外は再スロー (SYS-UT-003)。
- 能力 gate: `Unsupported` step の計画は検証拒否、能力表の版が engine と不一致なら実行前に
  `CapabilityUnavailable` で engine を起動しない (SYS-UT-006)。

### 増分#6: storage seed (node:sqlite)
