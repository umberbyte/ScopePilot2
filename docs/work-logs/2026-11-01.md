# 2026-11-01 作業記録

## DVWA固定ワークフロー診断の汎用HTTP診断化

### 背景

- 旧 `workflow-scan.ts` は `login.php`、`security.php`、`/vulnerabilities/**` と
  low / medium / high の切替を前提とし、DVWA以外へ適用できなかった。
- Desktopも `/vulnerabilities/` を含む認証済み候補だけを実行対象にしていた。

### 変更

- 採用済み候補のURL、HTTP method、観測済み入力点から検査対象を組み立てる
  汎用HTTP診断へ置換した。対象製品の画面名、URL構成、セキュリティレベルを仮定しない。
- 自動検査はセキュリティヘッダー、Cookie属性、CORS、内部エラー露出、DOM source/sink、
  入力反射、SQLエラー差分、オープンリダイレクト、パストラバーサルの9観点。
- 認証済みroleがある場合は既存session cookieをorigin固定transportへ渡す。資格情報を再利用して
  対象固有のログインをやり直さない。未認証対象でも実行可能。
- 元のbody値を保存していないPOST/PUT/PATCH候補は、本文を推測して送らず理由付きskipとする。
- transportは任意のHost/Cookie/Authorization上書きを拒否し、追加headerはorigin固定通信にだけ適用する。
- UIの有効化条件を `/vulnerabilities/` 判定から採用済みHTTP/HTTPS候補の有無へ変更した。
- 直接送信する4ペイロード（反射marker、SQL引用符、外部redirect、POSIX path traversal）を
  レビュー済みpayload catalogへ追加し、版を `2.1.0` に更新した。
