# 2026-10-23 診断報告書 v2

## 実装

- 顧客提出用の情報構造を `ReportDocumentV2` として定義した。
- 案件に `ReportSettings` を追加し、提出先、発行者、版数、文書状態、診断期間、総合所見、優先事項、制約などを明示入力できるようにした。未入力値は観測日時などから推測しない。
- 案件、対象 URL、ロール、ツール警告、担当者所見、Bruno確認、証拠参照から構造化レポートを生成する `ReportDocumentV2Builder` を追加した。
- `scopepilot-assurance-ja-v2` の DOCX レンダラーを追加した。表紙、文書管理、経営層向け概要、診断範囲、カバレッジ、評価方法、指摘一覧・詳細、対応計画、証拠索引、特記事項を出力する。
- ［診断レポートを出力］で、従来の Markdown、JSON、HTMLに加え、`report-document-v2.json` と `engagement-report.ja.v2.docx` を同時生成する。
- URL のユーザー情報・クエリ・フラグメントを除去し、HTTPヘッダー、JSON、フォーム形式の秘密値を伏せ字化する。原本は相対パス、SHA-256、証拠 ID で追跡する。
- 従来の Markdown と説明文から第三者サンプル報告書への参照を削除した。

## 検証

- v2専用テスト3件で、モデルの集計、秘密値の非露出、証拠と指摘の関連、Open XML妥当性、既存出力との同時生成を確認した。
- 全テスト186件のうち180件合格、4件スキップ。2件は同梱Playwright runtimeがローカルに存在しないため失敗し、今回の変更とは無関係。
- 架空案件から生成したDOCXをMicrosoft WordでPDF化し、全ページの表、改ページ、ヘッダー、フッター、伏せ字を目視確認した。

## 増分: 指摘詳細のHTTP証跡と高度な明細レイアウト

- ZAP Automation Framework のJSON出力を `traditional-json-plus` へ変更し、各警告の代表Request/Response、攻撃入力、観測根拠、追加情報を診断原本へ収集するようにした。
- ZAP原本は従来どおり案件フォルダーに保存し、プロジェクトJSONには証拠参照（相対パス、JSON Pointer、SHA-256）のみを保持する。報告書生成時に原本のハッシュとPointerを照合して詳細を読む。
- `ReportTechnicalEvidenceV2` を追加し、Request、Response、診断入力、観測根拠、外部サービスインタラクション、収集状態を指摘単位で構造化した。
- 提出用HTTP証跡ではAuthorization、Cookie、Set-Cookie、token、password、API key、メールアドレス、個人情報を示すJSONキーを伏せ字化し、24,000文字で表示を制限する。原本値はDOCXおよび構造化提出JSONへ複写しない。
- ZAPの説明・対策・CWE・CVE・参照URLも原本から取り込み、CVSSは値がない場合に推測せず「未入力」とする。危険度、発生可能性、成立状態、検出確度は別項目として表示する。
- 指摘詳細を、黒いラベルセルの概要表、説明、灰色コード領域のRequest/Response、診断入力・観測根拠、外部サービス観測、想定影響、改善策、参考情報の順に再設計した。短いHTTP証跡はページ途中で分断しない。
