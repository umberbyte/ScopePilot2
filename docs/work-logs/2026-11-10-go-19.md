# GO-19: Findings / Report (P6)

## 実装

- design 40 は本ブランチには存在しないため、`umberbyte/advanced-mode-redesign:docs/design/40-advanced-mode-redesign.md` の P6・A60〜A62 を読み取り参照した。
- A60 `adv.results.findings`: 一覧・検索・状態/重要度フィルタ・グループ表示、詳細、所見ごとの検証下書き、既存契約に沿った再現結果・重要度根拠・任意 CVSS の保存。保存済みの操作者・時刻・検証記録を別表示する。旧 `findings` route も維持した。
- 明示的な重複統合を追加。理由・操作者・時刻・統合先を保持し、元の証拠と人の検証記録は削除しない。統合先の状態を自動確定せず、統合チェーンと循環を拒否する。
- A61 `adv.results.evidence`: 証拠一覧・検索・hash・所見との相互導線、取得済み HTTP の表示用リクエスト行とレスポンス状態。`GET /api/evidence[?evidenceId=...]` は原本本文・任意 metadata・保存先・秘密ヘッダーを返さない。表示は派生情報であることを明示する。
- A62 `adv.results.report`: 複数ガイドライン選択、Low/Info の任意除外、正規モデルの Markdown プレビュー、既存 desktop bridge による DOCX/Markdown・保証レポート・技術付録・JSON・manifest の保存。ガイドライン・除外指定の変更時にプレビュー・AI案・保存リンクを失効させる。
- AI 文章案は明示操作で生成し、出典と未検証表示を付けて別枠表示。保存する正規レポートの本文・modelHash・モデルには混ぜない。
- Alerts はエンジン由来の未検証候補として同一 Findings 台帳へ取り込み、重複観測を集約する。人の確定/棄却と engine の `unverified` を区別する。正規 Markdown に人の検証記録と手動統合の履歴も掲載する。
- 新規 API・Finding の review/merge・EvidenceView を OpenAPI と TypeScript 契約へ反映。結果画面の ja/en 文字列を専用資源に集約した。

## 表示の境界

- 本文・ヘッダー値・クエリ値は証拠 API の表示派生では省略する。未対応の証拠形式や HTTP 未取得時は metadata のみで、再現 request/response を生成・推測しない。原本は従来のローカル evidence store に保持する。
- 既存証拠台帳には ScopePilot job/run と証拠の確実な関連付けがない。`sourceJobId` / `sourceRunId` は null とし、画面に「関連付け未記録」と表示する。ZAP 内部 run ID を ScopePilot job ID として扱わない。
- 共有用コピーは証拠ブラウザでは生成しない。DOCX/Markdown 保存には Simple と同じ案件フォルダ・既存 report export 契約を使う。
- GO-13 の scan-policy、active-scan-screen、scan-policy-screen、ZAP active-scan policy ファイルは変更していない。
