# GO-16: Advanced の Context / Authentication / Users / Session management

## 実装

- A09 に案件の Context（許可・禁止 Origin）、ユーザー表示名・業務ロール・認証方式・有効/無効、フォームからの LoginFlow 作成、保存済み flow の選択・編集、セッション維持確認を追加。
- Context は既存の Case API と revision guard を利用。ユーザーは既存の role/session identity に関連付け、Case/Auth サービス内で管理する。業務ロールの設定は認可の付与ではない。
- 実行可能なのは Form の browser login。Bearer / Basic / ApiKey / Cookie / Manual は設定のみ。SSO/MFA の人手介入、OS Vault 登録、自動再認証は公開しない。認証設定と flow は既存と同様にメモリ内のみで、案件を閉じると失われる。画面で制限を開示する。
- 維持確認は既存の InteractiveBrowserPort と role 別 BrowserSessionState を使用し、期待 URL、HTTP 状態、非空のログイン指標を検査。結果・時刻・flow 版・adapter 版だけを証拠へ保存する。認証切れ・確認不能、ユーザー/scope/flow の変更、再ログイン失敗では古いセッションを破棄する。同時確認は identity ごとの single-flight、遅れて完了した login は新しい session を上書きしない。
- 実ブラウザでは scope routing に加え Chromium の request-stage interception を用い、HTTP redirect の各 hop を送信前に検査する。service worker と別ページからの送信を拒否する。確認済み対象は loopback の所有 fixture のみ。
- refresh と cookie 名割当は fixture であり、実セッション更新ではないと開示する。login adapter が接続された構成では fixture refresh を拒否し、都度入力での再ログインへ誘導する。fixture refresh の single-flight / retry guard は role 別に分離した。
- UI/core 契約型、OpenAPI、経路表を更新。秘密値を設定 API に混入させない。login の秘密値は成功/失敗の双方で入力欄から破棄し、adapter 例外の内容は API に返さない。

## 設計と境界

指定された design 40 はこのチェックアウトには存在しないため、design 08、F09、既存 A02/A09 に合わせた。GO-13 の active scan / scan policy 画面と scan-policy ドメインは変更していない。既存の共通 application service / API では Case/Auth 部分だけを拡張した。
