# 2026-10-20 作業記録

## 旧 ScopePilot を参照した案件ワークスペース実装

- 旧版 `PROJECTS-AND-HANDOFF.md`、`ProjectPaths`、`ProjectWorkspaceService`、探索・候補選定・
  ZAP引き渡しを参照し、画面構造ではなく案件運用と安全制御をScopePilot2へ反映した。
- Simple S01 を native dialog のパス保持だけから、案件ワークスペースの作成・再オープンへ変更した。
  - 新規案件は空フォルダーだけに作成する。
  - 既存案件は `scopepilot.db` があるフォルダーだけを開く。
  - `inputs/`、`evidence/blobs/`、`runs/`、`exports/`、`reports/`、`backups/`、`locks/` を作成する。
- 受領資料は `inputs/` へ一時ファイル経由でコピーし、コピー前後のSHA-256を照合する。
  DBへ原名、相対パス、SHA-256、byte数、取込日時を保存する。同一原名・hashは再取込しても重複しない。
- migration v2 として案件UI設定と入力資料台帳を追加し、案件・最新認可・実行履歴・証拠保存を
  案件直下DBへ接続した。API service は案件切替時に新しいservice instanceへ切り替え、別案件の
  in-memory状態を持ち越さない。
- S01へ開始URL、許可/補助Origin、対象role、禁止操作、AI provider（zcode/Codex/Claude）とmodelを追加。
  探索seedは固定fixture値ではなく開始URLを使用する。
- S07はMarkdown表示だけでなく、案件 `reports/` へMarkdownと日本語DOCXを保存する。
  DOCX生成は設計17で決定済みの`docx` 9.11.0を固定した。AI adapter未接続時は、選択AIが生成したと
  誤表示せず、検証済みreport modelからの生成であることを画面に明示する。

## zcode / Codex / Claude AI連携

- `AiProviderAdapter`相当のデスクトップ境界を実装し、案件設定で選択されたCLIを実際に起動する。
  - zcode: `--attach`で受領資料を渡し、plan modeかつBash/Edit/Write/Web系tool禁止で実行する。
  - Codex: `codex exec --ephemeral --sandbox read-only --output-schema`で実行する。
  - Claude: `--print --restricted --tools Read --json-schema --no-session-persistence`で実行する。
- 受領資料解析は明示操作で実行する。資料内の命令をデータとして扱うpromptを固定し、JSON Schema、
  許可Origin、秘密値除去、件数・長さ上限を通過したURL・認証所在・PII/決済優先度・parameterだけを
  未確認document hintsとしてCoreへ登録する。資料だけから観測や所見は作らない。
- 報告書生成ではAIに検証済みreport modelを渡し、エグゼクティブサマリー・総合評価・推奨事項・
  限界だけを構造化生成させる。AIにないURLの追加を拒否し、ScopePilot検証済み原本を必ず末尾へ
  そのまま保持する。CLI未導入・未ログイン・失敗時は決定論的レポートへfallbackする。
- migration v3で`ai_invocations`を追加し、task、provider/model、入出力hash、成功/失敗、検証後提案を
  案件DBへ保存する。秘密値を含み得る生のCLI出力は保存しない。
- unit testではCLI runnerを差し替え、JSON envelope、scope外URL除去、query除去、秘密値redaction、
  AI報告と検証済み原本の併存、監査記録を検証した。E2Eでは課金を消費しない無効化フラグを用い、
  fallback経路を検証する。
