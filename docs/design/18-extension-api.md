# 18 拡張と独自検査 概要設計

対応要件: 仕様書 F20（拡張と独自検査）

## 1. 目的

公開API・隔離ワーカー・版付きルール・無効化・検証環境を提供し、独自検査を安全に追加できる
ようにする。既存 BApp の直接実行・互換は目指さない（非互換として明示）。

## 2. 再利用する現行資産

- ZAP/Nuclei アダプター（01・16）と能力表（IEngineCapability）
- ルール版管理（21のUpdateManager）と PayloadSet（05）

## 3. コンポーネント構成

```text
ProductApi（新規・loopback）:
  CLI・外部スクリプトから案件・計画・実行・結果を操作するローカルAPI（OpenAPI定義を同梱）。
  認証は実行ごとのトークン・loopback限定（4.1の内部連携規定）
RulePackage（新規）:
  独自検査の定義単位: 種別（RequestTemplate/Script/ExternalTool）＋入力（PayloadSet参照）＋
  判定条件＋版・hash。Script種別は隔離ワーカー（別プロセス・資源制限・ネットワークは
  管理された送信経路のみ）で実行
ExtensionHost（後段）:
  ワーカープロセスの起動・停止・タイムアウト・出力取込。案件証跡への自動記録
```

- ExternalTool 種別で外部診断ツールを追加する場合も、能力単位の検証（送信経路・ファイル参照・
  出力形式）を経てから有効化（21と同じ審査フロー）。

## 4. データモデル

- `RulePackage`（版・hash・供給元・審査状態）と実行記録への版固定。無効化は実行時計画から除外。

## 5. 安全制御と証跡

- 拡張の送信はすべて Orchestrator の計画を通す（直接ソケット禁止をワーカー契約に明記）。
  loopback制限・プロセス分離だけで安全と扱わない（6.1）。
- Script の能力宣言（ファイル/ネット/ヘッドレス）を必須とし、宣言外の能力利用は実行時検知で停止。

## 6. UI / CLI

- 「拡張」画面: RulePackage一覧（版・審査状態・有効化）。APIドキュメントへの導線。
- CLI: `scopepilot rule list|enable|disable`。
